# 通用设计参考图鉴生成 Prompt

生成一套具有统一版式的设计参考图鉴，共 **4 张彼此独立的图片，每张包含 5 个案例，共 20 个案例**。

本 Prompt 只规定图鉴的外层版式、视觉系统和输出形式。具体主题、案例分类、案例名称、说明文字以及演示内容，由执行 Agent 根据用户当次任务自主选择，不在本 Prompt 中预设。

## 一、主题与内容适配

执行 Agent 根据当前任务确定主题，并为四张图片安排相关案例。标题、英文名称、中文名称、关键词和演示内容应围绕该主题生成，不保留与本次主题无关的内容。

图鉴可以用于完整页面、局部组件、交互行为、动态过程或其他设计对象。根据对象选择适合的展示方式，不强制所有主题都采用完整网页截图，也不强制所有案例都展示动画关键帧。

如果提供了参考图片，沿用其外层布局、字体层级、背景、间距和框架。参考图片中的具体主题与案例不构成本次内容限制。

## 二、图片数量与输出形式

必须输出 **4 张独立的 3:4 竖版图片**，每张都是一个完整的图鉴页面。每张图严格包含 5 个纵向排列的案例区域。

禁止将四张完整页面拼接在同一个画布中。禁止四宫格、2×2 拼图、四页联系表或需要用户手动裁切的超长图。

每页内部的五个案例属于正常图鉴排版。单个案例内部可以包含必要的状态对比、局部细节或过程演示，但不能在其中再次嵌套整张图鉴页面。

页码默认使用 01–04；如果正在延续已有系列，则接续该系列已确定的页码。

## 三、整体视觉系统

采用设计参考手册与编辑式图鉴的视觉语言。背景使用非常浅的暖灰白，主要文字使用深灰或近黑色，辅助说明使用中灰色。页面保留清楚的阅读层级，避免大面积装饰、复杂底纹和与主题无关的图形。

四张图片的页面比例、背景、外边距、标题位置、字号层级、案例高度、左右分栏、分隔线、外框圆角和阴影必须保持一致。第一张确定外层母版，后面三张复用该母版，仅替换页码与案例内容。

图鉴外围采用固定的视觉系统。右侧案例内部的配色、字体、材质、组件和表现形式，由执行 Agent 根据案例需要决定，不强制套用同一种界面皮肤。

优先保证文字和案例可辨认。不要依靠极小字号塞入大量信息，也不要为了填满画布增加无关说明。

## 四、页面顶部布局

顶部设置统一标题区域，高度约占整张图片的 10%–12%。左右外边距保持一致，建议约为画面宽度的 4%–5%。

左上方放置主标题，格式为：

「[主题名称]设计参考 01」

后续页面只更换页码。主题名称由执行 Agent 填写，方括号与占位说明不得出现在成图中。

主标题下方放置小号英文副标题，可使用与主题对应的英文名称，或统一使用：

DESIGN REFERENCE

右上角可保留两至三行小号辅助文字，其内容由执行 Agent 决定。辅助文字不承担主要说明任务，也不得抢占标题空间。

标题过长时，可在固定标题区域内合理换行。四张图片必须采用相同的换行逻辑和字号层级，不允许单页标题挤压下方案例。

## 五、五行案例的固定布局

标题下方安排五个等高的横向案例区域，从上到下排列。四张图片中的对应行应处于相同位置，各行保持一致的上下间距。

每行采用「左侧信息区 + 右侧演示区」结构。左侧约占该行可用宽度的 26%，右侧约占 74%，两区之间保留固定间隔。比例以视觉均衡和内容可读为准，不因个别案例随意改变。

行与行之间通过留白或极细浅灰分隔线区分。避免粗重边框，不给每一行叠加多层卡片。

左侧文字起点、编号位置、右侧演示框起点、上下边缘应在五行之间严格对齐。底部保留正常页边距，不让第五个案例贴近画布边缘。

### 左侧信息区

每个案例的信息按以下层级排列：

- 浅灰色编号，默认每页从 01 排到 05。
- 英文案例名称与中文案例名称。
- 两至四组简短关键词，用于提示主要特征。

编号明显但不压过名称。名称可以适度换行，四张图片保持相同的字号和行距规则。关键词使用小号文字，必要时采用中英文两列，但不写成长段解释。

名称、关键词和说明由执行 Agent 根据具体内容生成。不要重复填充相同的泛化词语，也不要为凑齐文字数量编造属性。

### 右侧演示区

每行右侧设置一个统一尺寸的横向展示框。外框的位置、大小、圆角、边距及轻微阴影在整套图中保持一致。

展示框内部用于放置当前案例的视觉演示。其内容应占据足够面积，让用户能辨认主要结构和设计差异，避免大框中只有一个过小的对象。

外框可以沿用参考图中的简洁窗口结构，但浏览器地址栏、工具栏或设备外壳仅在适合主题时使用。不要为了统一外观，给所有对象强行套上完整网站或手机模型。

## 六、演示区的自适应规则

根据案例性质选择展示方式，同时保持外层展示框不变。

静态设计对象可以采用一个主要示例，配合少量必要的局部细节。局部组件应放大到能够看清文字、边界、图标和内部层级，不必展示与其无关的完整页面。

涉及状态变化的对象可以横向排列多个状态。涉及连续运动的对象可以展示三至五个关键帧，并使用细箭头、轨迹或简短状态标签连接。

涉及结构或布局关系的对象可以使用局部放大、对照视图或简洁的层级标注。所有辅助表达都应服务于理解当前案例，避免演变成密集的技术说明图。

同一案例中的多个状态，应保持对象身份、文字内容和基本视觉特征连续。不要用彼此无关的示例代替状态变化或过程演示。

演示区底部可以保留一行小号说明。是否需要参数、状态名称或其他标注，由执行 Agent 按主题决定；没有必要时不添加。

## 七、系列一致性与质量检查

检查四张图片是否具有相同的外层母版，尤其是标题区域高度、左右分栏、五行位置、编号、字号、演示框和页边距。

检查每张图片是否恰好包含五个案例，名称与右侧演示是否对应。案例差异应由实际设计内容体现，不依靠只换标题、颜色或关键词制造区别。

检查主要文字是否清楚，长名称是否合理换行，演示对象是否过小。减少无意义的小字、重复标签、装饰性数据和无法解释的符号。

不得出现占位符、未替换的主题名称、乱码、被裁断的标题、错位编号或超出展示框的关键内容。不要为任何案例虚构真实品牌背书、用户规模或效果数据。

## 八、独立生成规则

实际生成时，分四次独立执行，每次只生成一张完整图鉴页面。

每次调用沿用相同的外层母版规范，只附带当前页的标题、页码和五个案例描述。不要在单次图片生成指令中同时安排另外三张完整页面。

最终交付必须满足：

**4 个独立图片文件 × 每张 3:4 竖版 × 每张 5 个案例。**

不得用一张包含四页的拼图替代四个独立文件，也不得要求用户自行拆分。
